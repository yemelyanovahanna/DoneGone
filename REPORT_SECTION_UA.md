# Індивідуальне завдання Етап 3 Автоматизоване тестування

Відповідно до третього етапу плану DoneGone створено Postman Collection із 30 REST API-запитів та 87 перевірок. Колекція перевіряє стан backend, реєстрацію й авторизацію, створення, отримання та зміну проєктів, повний CRUD завдань, статистику Kanban-дошки та помилкові запити. Використано унікальні тестові email; JWT та ID зберігаються лише у змінних колекції під час запуску.

Для повторюваних перевірок створено окрему Docker Compose конфігурацію з frontend, backend та PostgreSQL. Newman запускається після готовності схеми бази даних і формує CLI, JUnit та стислий JSON-звіт. Тимчасові контейнери, мережа й тестовий volume видаляються після завершення.

Jenkins Pipeline доповнено стадіями Install Newman та API Tests with Newman. Фінальний локальний запуск #5 завершився SUCCESS: усі 87 перевірок пройшли. У контрольному запуску #4 очікуваний HTTP-статус навмисно змінено з 200 на 201. Newman повернув код 1, збірка завершилася FAILURE; API Gate Passed та Push Docker Images були пропущені через попередню помилку.

Перевірку виконано в окремому локальному Jenkins. Джерелом коду був локальний знімок замість SCM, а публікацію GHCR вимкнено параметром PUBLISH_IMAGES=false. Тестування реальних REST endpoint, Docker Build, Compose, Newman, JUnit і блокування конвеєра виконано фактично. Доставлений Jenkinsfile зберігає checkout scm та попередню GHCR-інтеграцію.

Мету третього етапу досягнуто: API-тести автоматизовано, їх виконання інтегровано з Jenkins, а помилки перевірок блокують подальші стадії.
