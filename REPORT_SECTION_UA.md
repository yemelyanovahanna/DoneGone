# 2. Індивідуальне завдання

## Умова завдання
Виконати перший етап поетапного плану індивідуального проєкту DoneGone — «Створення основи проєкту та CI».

## Хід виконання
На першому етапі було створено базову структуру вебзастосунку DoneGone. Застосунок побудовано за клієнт-серверною архітектурою та розділено на frontend, backend і database.

Frontend реалізовано на React. Створено початковий інтерфейс Kanban-дошки з чотирма колонками: To Do, In Progress, Review та Done. Для демонстрації базової логіки реалізовано переміщення завдань між сусідніми статусами.

Backend реалізовано на Node.js та Express. Створено REST API для реєстрації та авторизації користувачів, а також CRUD-операцій з проєктами й завданнями. Для авторизації використано JWT, а паролі перед збереженням хешуються за допомогою bcrypt.

Для зберігання даних використано PostgreSQL. Створено таблиці users, projects і tasks та зв'язки між ними.

Для базової перевірки працездатності backend створено unit/API-тест для endpoint `/health` з використанням Jest та Supertest.

Також створено Jenkinsfile, який описує базовий CI-процес і містить етапи Checkout, Install, Lint та Unit Tests. Після підключення Jenkins до GitHub через webhook такий pipeline може автоматично запускатися після внесення змін до репозиторію.

## Основні створені файли
- `frontend/src/App.jsx` — початковий інтерфейс Kanban-дошки;
- `backend/src/app.js` — конфігурація Express-застосунку;
- `backend/src/routes/auth.js` — реєстрація та авторизація;
- `backend/src/routes/projects.js` — CRUD для проєктів;
- `backend/src/routes/tasks.js` — CRUD для завдань;
- `database/init.sql` — структура бази даних PostgreSQL;
- `backend/tests/health.test.js` — автоматизований тест;
- `Jenkinsfile` — базовий CI-конвеєр.

## Результат
У результаті виконання першого етапу було підготовлено початкову версію DoneGone з базовою структурою frontend, backend та PostgreSQL, реалізовано основні операції з проєктами і завданнями та підготовлено базовий Jenkins CI-процес для автоматичної перевірки коду.
